\begin{abstract}
A whole-command cache misses when a reference database is replaced, because the reference bytes changed.
Hand-built incremental search repairs one tool's scores in that tool's code.
This paper centres on one generic fitter.
With no per-tool code, it infers for an unmodified CLI $F(\mathrm{records},\mathrm{reference})$ that the output decomposes over reference entries, and which numeric columns carry a global normalizer drawn from a closed family: identity, entry count, total entry length, or per-key row count.
Ties are broken by an entry-length partition.
If no member fits, or a tie survives, the fitter refuses and the caller runs the tool once on the whole reference.
A later release then reruns only changed entries, merges, and rescales.
The prior-art verdict on that pair of inferences is narrow.
iBLAST, iSeqSearch, and GeStore are hand-built per tool.
KumQuat infers input-stream combiners and does not fit a normalizer.
Record-side reuse with a copy-aware minimal key is secondary.
Safety is infer-or-refuse.
The probes are credited mechanisms, not a novelty claim.
On \texttt{hmmscan --cut\_ga} the fitter ships the measured contract, and it refuses the same argv without that flag.
Locked record-side cumulative wall speedups on hmmsearch are
$2.740\times$ and $6.847\times$;

$1.856\times$ and $4.404\times$.

$4/224$.

A cache keyed by the reference file sees a miss on every query.
The unchanged models are the reusable work, if the tool's output on a reference is the merge of its outputs on the entries, up to a normalizer the merge can reapply.

Whole-command incrementalizers already wrap unmodified binaries.
Rattle, Riker, ProcessCache, and INCR skip a command when its traced inputs are unchanged~\cite{spall2020rattle,curtsinger2022riker,shiptoski2023processcache,xie2026incr}.
A new Pfam release changes the reference argument, so the command reruns.
Hand-built incremental search does the reference-side job for one tool family.
iBLAST writes a Karlin--Altschul or Spouge repair for NCBI BLAST~\cite{dash2021iblast,karlin1990significance}.
iSeqSearch copies that rescale onto m8 producers, including DIAMOND~\cite{yoo2025iseqsearch}.
GeStore incrementalizes unmodified genomics tools with a per-tool plugin; its BLAST plugin repairs E-values and its HMMER plugin does not~\cite{pedersen2014gestore}.
KumQuat infers a combiner for an unmodified Unix command split on its input stream~\cite{shen2022kumquat}.
The combiner language has no global scale factor tied to a reference.

The contribution is the following, and nothing further.

\begin{enumerate}
  \item \textbf{Primary: reference-side contract inference.}
  One generic fitter, with no per-tool code, infers for an unmodified CLI $F(\mathrm{records},\mathrm{reference})$
  (a)~that the output decomposes over reference entries and
  (b)~which numeric columns carry a global normalizer, and its form, from a closed family (identity, entry count, total entry length, per-key row count), with a tie-break partition and refusal.
  This enables re-annotation across reference releases by rerunning only changed entries.
  The prior-art verdict is \textbf{narrow}.
  The surviving claim is the sentence in the prior-art pass: no prior system infers, for an unmodified CLI and with no per-tool plugin, both that the output decomposes over reference entries and which numeric columns are global normalizers of a form fitted from a small fixed family, so that a later reference release can rerun only new or changed entries and rescale those columns.

  KumQuat is input-side only.
  \item \textbf{Secondary: record-side reuse with a copy-aware minimal key.}

  Transport fields are spliced from the new record.

\section{Design}
\label{sec:design}

Figure~\ref{fig:arch} is the wrapper.
Phase one probes an unmodified binary and either emits a contract or refuses.
Phase two, on later inputs, runs the binary only on the work the contract says is new, then merges.
Two stages are the contribution: reference-side inference, and the rescaling merge that uses the fitted member.
Record-side key inference is the secondary mechanism.
Safety probes are the gate.

\subsection{What is inferred}
\label{sec:contract}

The tool is an unmodified function of two argv-named inputs, $F(\mathrm{records},\mathrm{reference})$.
The fitter does not read the tool's source, a manual, or the environment.
Inputs outside argv are fault class F6 and stay outside the guarantee (\S\ref{sec:limits}).
A per-format parser splits the reference into entries and exposes each entry's length.
Parsers in scope are HMMER3 profile text (length is the \texttt{LENG} integer; volatile tags are \texttt{DATE}, \texttt{BM}, \texttt{SM}, \texttt{COM}), FASTA (length is the residue count), and a one-line fixture format used only in tests.
Length is data on the parser.
The fitter refuses if the format has no parser or a profile has no \texttt{LENG} line.
Entry identity is the SHA-256 of the entry after volatile lines are dropped.
An entry whose hash is stable across a release is the unit of reuse.

\subsection{Record side}
\label{sec:record}

A record's fields partition into a dependency set $D$ and irrelevant fields.
Inside $D$, transport fields $U$ are those whose perturbation reappears at fixed output positions and changes nothing else.
The copy-aware key is $K^{\ast} = D \setminus U$.
The cache stores the produced fields under a hash of $x|_{K^{\ast}}$ and splices the new record's transport fields on a hit.
Joint transport---the same identity when every transport field is substituted at once---is tested on the probe sample.
It is not proved for the whole domain.
The minimality argument in \S\ref{sec:formal} says that, when joint transport holds, $K^{\ast}$ is a sound splice key and no smaller sound splice key exists.
Dependency inference that keys all of $D$ is prior art (\S\ref{sec:rw}); the secondary claim is the split that drops pure copies from the key.

\paragraph{Decomposition.}
The primary probe draws

The fitter ships decomposition only together with a completed normalizer assignment, and only when the union of the parts matches the whole under ref-merge: equal row-key sets, byte-identical non-numeric columns, byte-identical identity columns, and the half-ULP predicate of \S\ref{sec:formal} on every linearly normalized column.

\paragraph{Closed family.}
A column is numeric when every aligned token parses as a finite float.
A mixed column refuses the argv.
The members, fixed before the fitter was run, are:
\begin{enumerate}
  \item \textbf{identity}: the printed token is byte-identical on every aligned row.
  \item \textbf{entry\_count}: rescale by $|R| / |R_{\mathrm{part}}|$.
  \item \textbf{total\_entry\_length}: rescale by $L(R) / L(R_{\mathrm{part}})$, with $L$ the sum of parser lengths.
  \item \textbf{per\_key\_row\_count} of an output table of the same run: rescale by the ratio of row counts for that record key.
  A zero denominator does not fit.
\end{enumerate}
No member's definition names a tool, a flag, or a HMMER statistic.
Entry count and per-key row count recover HMMER's database size and its per-sequence reported-target count when the probe says so.
A candidate fits when every aligned row satisfies the consistency predicate.
Two candidates that agree with each other on every row, within that predicate, are one candidate.
An all-zero column collapses to identity.

\paragraph{Tie-break and refusal.}
A primary split that balances both entry count and total length gives the same factor to both size measures, so they tie even when only one is the law.
The disambiguating partition orders entries by length descending, then by content hash ascending, and fills one part until it holds at least half the total length and is a proper subset.
The complement is the other part.
A tied candidate survives only if it still fits.
If the probe leaves zero members, or more than one distinct member, the column refuses.
A column that no candidate fits refuses the whole reference-incremental path for that argv.
The caller runs one full $F$ and does not splice a partially fitted column into the output.
This is stricter than the earlier column-wise rule that recomputed a single non-fitting column and reused the others.
\texttt{--cut\_ga} and the default threshold are different contracts.

The primary partition used for new references is a Fisher--Yates shuffle on \texttt{random.Random(seed).random}, not CPython's \texttt{shuffle}, then a cut into parts whose sizes differ by at most one.
The pinned check is seed
$20261006$

and
$n = 4$:
% source: pipeline/docs/REFERENCE_INCREMENTAL_PROTOCOL.md guard n=4

$[0, 3, 2, 1]$.
% source: pipeline/docs/REFERENCE_INCREMENTAL_PROTOCOL.md Fisher--Yates guard

T1 and T2 do not use it.
They reuse halves already drawn by the kill-test script.

\subsection{Merge and rescale}
\label{sec:merge}

On a new reference the fitter hashes entries into unchanged, changed, and removed.
Removed rows are dropped.
Unchanged rows are reused.
Changed and new entries are scanned as a sub-reference, after the caller-declared index command (\texttt{hmmpress} for HMMER; the command is data, not a compiled tool name).
Cached numeric cells are multiplied by the fitted factor from the old reference to the new one.
Cells produced on the sub-reference are multiplied by the factor from that sub-reference to the new one.
For entry count those factors are $N'/N$ and $N'/|\mathrm{changed}|$.
For total entry length they are the corresponding length ratios.
Per-key row counts are computed from the merged row set after the merge, because the normalizer depends on which rows survived.
The value is re-printed with the source token's significant digits.
Identity columns are copied as bytes.

\section{Formal model}
\label{sec:formal}

The statements below are the definitions used by the fitter and the consequences of those definitions under the assumptions written next to them.
They are not claimed as theorems about HMMER beyond what the probes measure.

\subsection{Decomposition and the family}

Let $R$ be a reference with $|R| \ge 2$, split into parts that are non-empty, disjoint, and exhaustive.
Write $\mathrm{keys}(F(X, R))$ for the set of row keys in the output.
\textbf{Decomposition} holds for a probe sample $X$ when, after the normalizer assignment,
$\mathrm{keys}(F(X, R))$ equals the union of $\mathrm{keys}(F(X, R_i))$, no key appears in two parts, non-numeric and identity columns are byte-identical on aligned rows, and every linear column satisfies the consistency predicate.
The fitter does not ship decomposition without an assignment.

The \textbf{normalizer family} is the four members in \S\ref{sec:reference}.
It is closed: a fifth measure, including Karlin--Altschul effective length, is outside the claim unless a later addendum marked post-hoc extends the family.
Results measured before that addendum would not confirm the extension.
The family is not the polynomial search of Zhang et al.~\cite{zhang2014mri}, which fits linear and quadratic relations between scalar outputs of a library function on affinely related numeric inputs.

\subsection{Consistency predicate}

For a printed token, let $\mathrm{dec}$ be the number of digits after the decimal point in the mantissa, or zero if there is no decimal point, and let $\mathrm{exp}$ be the integer exponent if the token contains \texttt{e} or \texttt{E}, otherwise zero.
\[
\mathrm{half\text{-}ULP}(\mathrm{printed})
  = 0.5 \times 10^{-\mathrm{dec}} \times 10^{\mathrm{exp}}.
\]
A part value $v$, rescaled by a finite factor $\phi$, is consistent with a whole value $w$ when
\begin{equation}
|v \phi - w|
  \le \mathrm{half\text{-}ULP}(w_{\mathrm{printed}})
    + \mathrm{half\text{-}ULP}(v_{\mathrm{printed}}) \cdot |\phi|.
\label{eq:consistent}
\end{equation}
This is the predicate the kill tests and the fitter implement.
Identity is the case $\phi = 1$ with byte-identical tokens.

\subsection{Ref-merge error bound}

The merge does not emit the real product $v\phi$.
It re-prints that product at the source token's precision.
Assume that the re-printed token $\mathrm{emitted}$ satisfies
$|\mathrm{emitted} - v\phi| \le \mathrm{half\text{-}ULP}(\mathrm{emitted})$,
and that the probe accepted the row under~\eqref{eq:consistent} with $\mathrm{source}$ the cached printed value and $\mathrm{stock}$ the full-run printed value.
The triangle inequality then gives
\begin{equation}
\begin{aligned}
|\mathrm{emitted} - \mathrm{stock}|
  &\le \mathrm{half\text{-}ULP}(\mathrm{stock})
    + \mathrm{half\text{-}ULP}(\mathrm{emitted}) \\
  &\quad + |\phi|\cdot \mathrm{half\text{-}ULP}(\mathrm{source}).
\end{aligned}
\label{eq:bound}
\end{equation}
Each half-ULP term is the quantity defined above, evaluated on that printed token.
This is the same bound as $\tfrac{1}{2}\mathrm{ulp}$ of each token.
The bound is a relation between printed numbers.
It is not a claim about the tool's real-valued score before printing, and it is not byte identity.
Ref-merge uses byte identity for hit sets, unnormalized columns, and identity columns, and~\eqref{eq:bound} for columns assigned a linear member.
If the re-print assumption fails for a format, \texttt{--verify full} is the check that compares the emitted table to stock.

\subsection{Break-even churn}

One later re-annotation, with the probe already defined, uses
\begin{align*}
T_{\mathrm{stock}}(n) &= a + b n, \\
T_{\mathrm{inc}}(n, c) &= a + c\, b n, \\
S(c) &= (1 - c)\, b n .
\end{align*}
Assumptions, all stated, none of them a new measurement:
$a$ does not shrink on a smaller reference;
$b$ scales linearly with the fraction of entries searched;
the two parts partition the entries, so their per-record costs sum to $b n_p$;
merge and rescale are ignored next to these terms.
The measured hmmscan wrapper is
$3.60\times 10^{-5}$
% source: computed w/P with w from pipeline/results/headline_screen.json hmmscan w.w_s and P=3a+2 b n_p = 529.5921593089842; ratio=3.5996899431797134e-05
of the primary probe cost below, so $w$ is left out of $P$.
Per-entry cost is not assumed uniform.
That is why a timed release run is required before a speedup is claimed.

With $k = 2$,
% source: pipeline/docs/REFERENCE_INCREMENTAL_PROTOCOL.md
the primary probe costs $P = 3a + 2 b n_p$.
The tie-break reuses the whole-reference run and adds two calls, for $P_{\mathrm{both}} = 5a + 3 b n_p$.
Savings on one later re-annotation exceed the probe when $b n > P$ and $c < c^{\ast}$, where
\begin{equation}
c^{\ast} = 1 - \frac{P}{b n}.
\label{eq:cstar}
\end{equation}
More releases only amortize $P$.

% source: pipeline/results/headline_screen.json:N

$c_{\mathrm{R1}} = 4052/30134 = 0.13447$

\subsection{Copy-aware key}

Assume joint transport, as defined in \S\ref{sec:record}, and that irrelevant fields do not affect the per-record function.
Then $K^{\ast}$ is a sound splice key: the output is determined by $x|_{K^{\ast}}$ together with the transport values written at their positions.
Every sound splice key contains $K^{\ast}$, because a field in $K^{\ast}$ left out of the key would have to be transport or irrelevant, contradicting the partition.
Recall is therefore at least as high under $K^{\ast}$ as under any larger sound key, including the full dependency set $D$.
The probes test single-field transport and one all-at-once substitution.
A violation they miss is a residual of the same kind as the probe miss rate in \S\ref{sec:rq1}, and the audit catches a hit-affecting fault with probability $1 - (1-q)^{h}$ on $h$ hits.
The argument does not extend past what the probes establish.

\paragraph{Hand-built reference incrementality.}
iBLAST wraps NCBI BLAST+, builds a delta database from filenames and sizes, and applies a Karlin--Altschul recount or a Spouge rescale $E_{\mathrm{total}} = E_{\mathrm{part}} \cdot n_{\mathrm{total}} / n_{\mathrm{part}}$ that the authors derive~\cite{dash2021iblast}.
``Automated'' means the user does not type the formula.
The partition is append-shaped growth of one tool, not a probed partition of an arbitrary reference.
iSeqSearch adopts that rescale for tools that emit m8, including MMseqs2 and DIAMOND, and judges E-values by correlation~\cite{yoo2025iseqsearch}.
It does not discover which column is normalized.
GeStore runs unmodified binaries, including BLASTP and HMMER, by rewriting inputs and merging outputs through an administrator-written plugin~\cite{pedersen2014gestore}.
The BLAST plugin corrects E-values following Turcu, Nestorov, and Foster (DaWaK 2008), as GeStore describes that repair; that PDF was not obtained in the prior-art pass.
The HMMER plugin only generates input files, and GeStore's Pfam accounting marks every update significant.
MMseqs2's \texttt{clusterupdate} mode is hand-built incremental clustering, not a search-result cache~\cite{steinegger2017mmseqs2}.
InterProScan's precalculated lookup and eggNOG-mapper's cache mode key the query sequence, not a diff of the member database~\cite{cantalapiedra2021eggnog,eggnog-cache-wiki}.
The HMMER daemon keeps one database resident for many queries~\cite{eddy2011hmmer}.
UniRule recomputes annotations from expert-written rules~\cite{macdougall2020unirule}.
Ensembl VEP's cache is a per-release data dump~\cite{mclaren2016vep}.
None of these infer both decomposition over reference entries and a fitted column normalizer.

\paragraph{Input-side decomposition, and a polynomial search.}
KumQuat synthesizes a combiner for an unmodified command so that $f(x_1 \mathbin{+\kern-0.2em+} x_2) = g(f(x_1), f(x_2))$, in a language of concat, merge, rerun, stitch, add, first, and second~\cite{shen2022kumquat}.
That is decomposition of an input stream.
There is no reference argument and no multiplicative database-size term.
Caruca classifies opaque commands as stateless, pure, or side-effectful and leaves aggregator synthesis to that line of work~\cite{lamprou2025caruca}.
INCR memoizes command effects; finer chunks require crowdsourced annotations and are keyed by bytes~\cite{xie2026incr}.
Zhang et al.\ infer polynomial metamorphic relations for numeric library functions by particle-swarm search~\cite{zhang2014mri}.
The relation is between two scalar outputs on affinely related inputs.
It does not partition a reference or identify a coefficient with a count of entries.
MapReduce and divide-and-conquer synthesis start from examples or a semantic model of a program, not from an opaque CLI and a statistical column~\cite{smith2016mapreduce,farzan2017divide}.
Incremental view maintenance and self-adjusting computation maintain a computation the user has already written down~\cite{blakeley1986views,acar2003selective}.

\paragraph{Record side, which is occupied up to the copy split.}
Whole-command caches are the systems above plus workflow task hashes~\cite{ditommaso2017nextflow,molder2021snakemake,cromwell-call-cache}.
IncPy and Mandala memoize inside a language runtime~\cite{guo2011incpy,makelov2024mandala}.
GREYONE infers which input bytes affect which values by mutation~\cite{gan2020greyone}.
DUST learns which URL components do not change page content~\cite{baryossef2007dust}.
Param Miner finds request inputs that change a response, including inputs reflected verbatim~\cite{kettle2018paramminer}.
A cache keyed by any of those dependency sets still contains copied fields.

\paragraph{Three attacks from the prior-art pass.}
The kill rule was fixed before the search: kill the claim if any prior system infers both (a) and (b) for unmodified black-box tools; narrow it if prior work does one of them automatically for one family, or hand-builds both for a specific tool.
The kill branch did not fire.
The narrow branch did.

\begin{enumerate}
  \item \textit{GeStore and iBLAST already did this, including HMMER.}
  GeStore's HMMER plugin does not rescale, and iBLAST's formula is BLAST-specific code.
  The defeat on disk is that pair of designs together with a fitter that has no per-tool branch.
  T1 passes on hmmscan and the length fixture ships total entry length on a column named \texttt{evalue}.
  A hand-coded HMMER plugin can be adjusted until T1 passes and still fail the length fixture.
  \item \textit{KumQuat already infers decomposition for black boxes.}
  Its equation splits the input stream, and the combiner language has no reference scale factor.
  A merge that demands byte equality is what the no-\texttt{--cut\_ga} run rejects: the union is a strict superset of the full run
  ($1{,}085$ vs.\ $1{,}082$ hits).
  % source: pipeline/results/reference_kill_r2n.json hits_union=1085 hits_full=1082
  That combiner would refuse or rerun.
  It would not fit entry count or per-key row count.
  \item \textit{The ASE 2014 search already infers the normalizer, because a rescale is a polynomial.}
  That search does not partition a reference, choose a table column, or tie the coefficient to a measured size of the reference.
  The experiment that would make the attack real is fitting the pre-registered family on partition probes of an unmodified CLI.
  T1 is that experiment for one argv.
  It is not a result in the ASE paper.
\end{enumerate}

The sentence the verdict leaves standing is the one in the introduction.
It does not say that incremental search is new, that E-value correction is new, or that black-box decomposition of an input stream is new.

\section{Limitations}
\label{sec:limits}

F6 is any input the tool reads outside argv: environment variables, unnamed paths, configuration beside the input.
The macOS probe run marks both F6-env and F6-file as unsafe-ship
($32/32$ each).
% source: pipeline/results/probe_eval_audit.md
Linux file tracing is the stated cover for F6-file and has no committed measurement here.
F6-env remains outside the guarantee.
The error bound~\eqref{eq:bound} is a printed-precision relation under a re-print assumption.
It is not bit identity of the tool's internal score, and a column whose law is outside the four members refuses rather than approximating.
Parsers are per format.
A reference format with no parser refuses; the fitter does not invent a length.
All wall-clock numbers in the committed timing files used above were taken on exclusive nodes of a university cluster (AMD EPYC 7542), except the probe-evaluation counts, which are a macOS measurement of decisions rather than of speed.
A speedup for the 38.1$\to$38.2 release is not among those numbers.

\section{Conclusion}

One fitter, with no per-tool code, accepts or refuses a reference-side contract for an unmodified CLI: decomposition over entries, and a normalizer from a four-member family, with a length tie-break.
On \texttt{hmmscan --cut\_ga} it ships entry count and per-key row count; without that flag it refuses.
Record-side reuse with a copy-aware key is the secondary result, and its locked speedups are reported next to the post-hoc correction the fit error requires.
The release-level speedup, the second search tool, and the whole-command baselines remain to be measured.
