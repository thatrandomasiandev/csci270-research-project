# W7 protocol — break-even gate

Date: 2026-10-19. Question: after the entry diff, does TARE run the stock
command when the changed fraction is above the break-even threshold, and
is that output the stock output?

This is a correctness check. Laptop wall times are not a speed claim.
W8 times Pfam 37.4→38.0.

## Semantics (written before the pilot searches)

The shipped command is `acts run --strategy reference --pin "-Z {entry_count}"`
with `hmmscan --cut_ga`. The pin is the exact-mode normalizer. The gate's
stock run, and the comparison stock run, use the argv without that pin.

`hmmscan` with more than one thread is not treated as a byte-stable oracle.
Both arms use `--cpu 1`, inside the two-thread cap.

A full-size call reads the caller's reference and does not prep it. Subset
files are `hmmpress`-ed first.

The gate fraction is the share of new entries whose content hash is not in
the cache. Volatile tags are DATE, BM, SM, and COM. A cold cache is a fill:
there is nothing to replay, and the threshold does not apply. The comparison
is strict (`f_delta > threshold`). The default threshold is 0.80, which is
`(1 - 0.152) / 1.06` from the laptop cost fit, used when the cache has no
usable fill/update history.

`--audit-p 0` keeps the recorded decision on the gate. Equality is a
separate stock comparison.

An empty body can match and still prove nothing. The query is proteins a
stock search of that subset reports, so the comparison has rows. The
changed fraction does not depend on which proteins those are.

Stock-vs-stock disagreement stops the check. That is a blind comparison,
not a gate failure.

The full Pfam files are about 330 MB compressed. Loading one into the
reference parser holds every model. That does not fit the 3 GB cap, so
both the pilot and the measured run use streamed subsets of Pfam 37.4 and
Pfam 38.0. The subset's own hash fraction is what the gate sees.

## Pilot

Seeds 20261211 (models) and 20261213 (query order). Genome
`GCF_024971875.1`, disjoint from the measured genome. Scratch
`~/tmp/tare_w7/`. Command: `nice -n 10 python3 scripts/w7_breakeven_check.py pilot`.

Addendum, same day, before lock. A first draw of 4 proteins chosen without
looking at hits produced no rows. The high arm still fell back
(`f_delta=0.900000`, threshold `0.800000`) and the empty tables matched,
but the low arm refused the pin check because the probe sample had no
rows. That draw could not show a replay. The pilot then kept the same
model seeds and took up to 4 proteins that the subset actually reports.
That is the run in `results/breakeven/pilot.json`.

That run passed.

- Comparator, before any search: identical, value-only, missing, extra, and
  order each returned the class with that name. A known-bad value change
  does not come back identical.
- High arm: 30 models, `f_delta = 0.9` (27/30), fill `SHIP` (cold cache,
  fraction 1.0, not a fallback), update `FALLBACK` with
  `fallback: f_delta=0.900000 > threshold=0.800000`. Stock-vs-stock
  identical. TARE vs stock identical on tblout (4 rows) and domtblout
  (4 rows).
- Low arm: 24 models, `f_delta = 0.0833` (2/24), update `SHIP`,
  `exact replay under pinned normalizer`, no fallback line. Stock-vs-stock
  identical. TARE vs stock identical on tblout (4 rows) and domtblout
  (3 rows).

## Measured run (locked)

Code is frozen at the commit that contains this file and
`results/breakeven/pilot.json`. The script refuses a dirty tree.

- Model seed 20261212. 40 accession stems from Pfam 38.0, excluding the
  54 pilot stems. Pfam 37.4 supplies the old versions of those stems.
- Query seed 20261214 shuffles the proteins that stock reports on that
  subset and keeps up to 8. Genome `GCF_021554655.1`. Pilot query ids are
  excluded. The two genomes are different files.
- Fresh cache. No cost history, so the threshold is the default 0.80.
- `--cpu 1`, `--audit-p 0`, `nice -n 10`, scratch `~/tmp/tare_w7/measured`.
- Minimum 20 models. Minimum 1 tblout row. Otherwise INCONCLUSIVE, not FAIL.

Order: stock twice, then fill on 37.4, then the update on 38.0.

- Stock-vs-stock not identical → INCONCLUSIVE.
- Fill decision `FALLBACK` → FAIL (the cold cache was gated).
- `f_delta <= 0.80` or no reported row → INCONCLUSIVE.
- Update `FALLBACK`, why starts with `fallback: f_delta=` and contains
  `> threshold=`, and both tables identical to stock → PASS.
- Otherwise, when the fraction is above the threshold → FAIL.
  Difference class is `run.tare_vs_stock.<table>.class`
  (identical / order / value-only / missing / extra / missing_and_extra / different_row).

Result file: `pipeline/results/breakeven/measured.json`.
